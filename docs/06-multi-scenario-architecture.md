# 多场景 Agent 通用架构

## 目标
在同一套 Codex + DeepSeek 工作台中支持 AI 编程、AI 短剧、AI 写作、AI 金融和 AI 法律五类任务。底座保持一致，领域能力通过场景规则、Skills、Agent 角色和 MCP 组合。

## 分层原则
1. **模型与运行时层**：Codex 负责工作区、任务执行、子 Agent 和审批；DeepSeek 作为可配置模型提供方。模型名、API 地址和密钥属于本机配置，不写进场景包。
2. **通用规则层**：根目录 AGENTS.md 约束任务拆解、证据、最小变更、验证和交付报告。
3. **场景层**：scenarios/<场景>/AGENTS.md 定义领域规则；prompts/scenarios/ 保存可复制的任务启动提示词。
4. **技能层**：.agents/skills/<技能名>/SKILL.md 封装可复用领域流程，说明触发条件、输入、步骤、输出和失败处理。
5. **工具层**：Scripts 执行确定性、可重复、可测试的操作；MCP 连接外部数据和系统；API/CLI 是特定系统的接入方式。
6. **治理层**：区分事实、推断和建议；注明来源、时间和限制；高影响动作先确认；交付物可检查。

## Agent / Skills / Scripts / MCP 分工
| 组件 | 适用职责 | 不应承担 |
|---|---|---|
| Agent | 角色分工、任务拆解、并行研究、交接和综合 | 不取代确定性脚本，不伪造工具结果 |
| Skills | 领域流程、检查清单、判断框架和格式规范 | 不把每一步都写成僵化脚本 |
| Scripts | 校验、转换、批处理、计算、文件整理和测试 | 不把不透明判断伪装成确定性结论 |
| MCP | 搜索、读取、查询、连接外部系统和数据源 | 不默认获得写入、交易、发送或删除权限 |
| Plugins | 打包分发 Skills、MCP 配置和资源 | 不等于模型，也不保证工具自动可用 |

## 统一任务闭环
需求澄清 → 计划与风险 → 资料/代码/数据采集 → 领域处理 → 独立校验 → 交付 → 复盘。

每次任务至少输出目标与范围、关键假设、来源/文件/工具及时间、已完成工作与验证证据、未完成项与风险、需要用户确认的外部副作用。

## 五个场景重点
- **编程**：先读仓库约定；先复现再修复；测试结果必须来自真实命令。
- **短剧**：明确受众、平台、时长、题材和商业目标；剧情、分镜、制作清单分阶段交付；标注版权和素材来源。
- **写作**：明确读者、用途、事实边界和文风；研究与写作分离；引用逐项可追溯。
- **金融**：使用可验证的行情、财报和宏观数据；注明时间戳、口径和缺口；预测是情景与概率，不是确定事实；禁止未授权下单。
- **法律**：确认司法辖区、日期、事实和文件版本；优先官方来源；区分条文、解释和风险提示；不冒充律师或承诺结果。

## 安全原则
- 不提交 API Key、Cookie、账户号、客户资料或真实交易凭证。
- MCP 最小权限，默认只读；写操作、资金动作、发送消息、发布内容和删除数据必须明确确认。
- 领域规则可用中文；工具字段、脚本参数、Agent ID 和 MCP server 名称保持稳定机器标识。
- 金融和法律等高影响领域保留来源和不确定性，不以模型输出替代专业判断。
- DeepSeek 配置独立于场景包，避免重复配置密钥和模型名。
